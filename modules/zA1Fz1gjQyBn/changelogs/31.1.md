This release brings official support for Googlebooks (Aluminium OS), including automatic firmware download suggestions and the ability to patch recovery GPT images directly onto a connected USB drive. Bringing Magisk to Googlebooks also meant supporting Android's Headless System User Mode (HSUM), where user `0` operates strictly as a non-interactive background system user while human users run in secondary user profiles. Adapting Magisk to HSUM created several architectural challenges, as many longstanding features and internal mechanisms were built around the assumption that user `0` is always the primary interactive user.

To address this, the way superuser access is granted to apps has been redesigned, and the traditional interactive root request prompt has been removed. The existing reactive `su` request flow, which relies on intercepting a root call in the background daemon and launching a blocking UI prompt in the right user session, is fundamentally incompatible with HSUM, especially when handling non-app UIDs like `adb shell` that are not tied to a foreground user. Instead, superuser access is now explicitly granted to applications ahead of time directly from the Superuser tab in the Magisk app.

Finally, the app hiding (package repackaging) feature has also been removed. Like interactive `su` prompts, the repackaging and stub management mechanisms are fundamentally incompatible with HSUM. More importantly, truly hiding an installed package from detection is nearly technically impossible on Android. Since interactive root prompts no longer require the Magisk app to remain installed at runtime and Magisk no longer automatically reinstalls the app if it is missing, the most effective way to hide the Magisk app is to simply uninstall it after configuring your superuser policies and modules.

## Changelog

- [General] Support Headless System User Mode (HSUM) devices
- [General] Drop support for Android 6.0; Android 7.0 is now the minimum supported version
- [General] Remove the app hiding (repackaging) feature and the stub app; Magisk no longer reinstalls the app automatically if it is missing
- [App] Remove reactive superuser request prompts; superuser access is now explicitly granted ahead of time in the Superuser tab
- [App] Unify the image patching pipeline across local files and remote URLs for raw images, OTA zips, factory image zips, Samsung Odin tars, and Aluminium OS recovery GPT images
- [App] Automatically suggest official firmware downloads for Google Pixel and Googlebook (Aluminium OS) devices
- [App] Support patching Aluminium OS recovery images and writing directly to a connected USB drive on Googlebooks
- [App] Display real-time in-place read/write progress and transfer speeds when downloading and patching images
- [MagiskSU] Remove obsolete superuser access mode and reauthentication settings
- [MagiskSU] Fix `-g`/`-G` argument handling, forward unknown options to the shell, and fix daemon exec signal handling
- [MagiskBoot] Support signing ChromeOS boot images natively and automatically re-sign on repack, removing the external `futility` binary
- [MagiskBoot] Fix AVB 1.0 ECDSA signature verification and signing by using ASN.1 DER encoding
- [MagiskBoot] Preserve Samsung `SignerVer02` signatures during boot image repack
- [MagiskBoot] Revert updating AVB hash descriptor image size on repack
- [MagiskBoot] Enable architecture-specific BCJ filters for XZ compression and improve `zImage` compressed payload detection
- [MagiskBoot] Support building `magiskboot` natively on Linux and macOS hosts
- [Core] Fix potential crashes when handling `NULL` database strings or failed daemon connections
