# Magic V2Ray v5.0 Release Notes

### Highlights

- **XDRIVE transport**: tunnel VLESS traffic through a shared cloud-drive folder (Google Drive, S3, ...), with the required mux enabled automatically.

- **Process-based routing**: route traffic by Android app (package name or "unknown apps"), backed by a built-in UID lookup server.

- **External API level 3**: unlimited routing rules and hosts, file-based overrides, custom geo databases and `policygroup://` connections.

- **32-bit Android support**: new `armeabi-v7a` and `x86` builds alongside `arm64-v8a` and `x86_64`.

### Added

- **XDRIVE transport (VLESS only)**

- New `xdrive` network in the node editor with service (`google-drive`, `s3`, `template`, `local`), remote folder, secret keys and raw XDriveObject JSON (`extra`) fields. FinalMask is supported as usual.

- Share links parse and serialize the XDRIVE settings (`service`, `folder`, `secrets`, `extra`).

- XDRIVE requires VLESS with encryption; mux is always enabled for these nodes, regardless of the global mux setting. Requires Xray-core v26.11.8 or newer.

- Localized labels and hints (English, Chinese, Traditional Chinese, Vietnamese, Russian).

- **Process-based routing rules**

- Match apps by package name or by unknown-app status, with an installed-app picker. Packages are resolved to UIDs when Xray rules are generated.

- Process conditions are supported in rule editing, summaries and JSON import/export.

- Android connection-owner UID lookups are served over a private local socket for Xray's process matching, kept alive together with Xray. A UID-based process finder is registered for routing process rules.

- A warning is shown when a process rule may not work (Android below 10, or RouteOnly disabled).

- **Source address and port routing rules**: match source IP and port across the editor, Xray configuration and External API, with import/export and documentation support. A default block rule is added for excluded apps.

- **External API level 3**

- Unlimited routing rules and hosts, overrides loaded from granted content URIs, and consent-gated custom geo databases used for a session.

- **Policy groups**: session-only `policygroup://` connections with 2-256 nodes and Xray balancing strategies, including node access handling, confirmation prompts and active-node reporting.

- Process selectors in routing overrides accept Android package names and `__unknown_apps__`.

- **Per-app activity logs**: connection and node-access requests are recorded per app and shown in Access permissions. Always-allowed apps are no longer prompted when their settings change, and the consent dialogs are simplified.

- API documentation and translations updated for all of the above.

- **Headless external connects**: approved external connection requests run in a hidden WebView hosted by a short-lived foreground service when the app has no screen, avoiding a flash of `MainActivity`. Falls back to the existing UI flow when headless setup is unavailable.

- **32-bit ABIs**: `armeabi-v7a` and `x86` binaries are built and packaged next to the 64-bit ones. Installer selection, CI artifacts and release metadata cover all four architectures.

- **Touch-friendly drag reordering** for categories and routing rules using pointer-based drag handles, with localized accessibility labels. Category order is persisted and routing-rule saves are debounced.

- **Unsaved changes prompt**: leaving Traffic or Network settings with unapplied changes offers apply, discard or stay.

- **Root mode** can now try the `adb testtun` hotspot for testing.

### Changed

- **WebUI sync**: the UI refreshes when it becomes visible, and live WebUI sessions are notified after Quick Settings tile or notification actions change the proxy state (with a delayed ping for teardown).

- **Observatory delay tests** now exclude handshakes.

- **Mux is now written at the outbound level** (`outbound.mux`), where Xray reads it. Previously it was emitted under `streamSettings`, so it may not have taken effect for regular nodes.

### Fixed

- **Excluded-app bypass**: IPv4 and IPv6 filter rules now reject excluded UIDs that send traffic through `xraytun0`, closing a bypass of the mangle-based exclusion. The hook and chain lifecycle is managed, with iptables tests covering add, remove and teardown.

### Notes

- XDRIVE needs Xray-core v26.11.8 or newer, plus VLESS encryption on both ends.

- Process-based routing works best on Android 10 or newer with RouteOnly enabled.
