Install through the KernelSU manager under Modules - Install from storage, then reboot.

The log showed the profile being applied three times on every boot:

```
13:45:23 已应用预设: balanced
13:45:23 initrc 服务已应用预设 balanced
13:45:24 已应用预设: balanced
13:45:36 已应用预设: balanced

```

`initrc` applies once, `service.sh` applies again, and `appwatch` applies a third time on its first poll because it started with an empty `last` and saw a change.

Each apply walks a few dozen nodes. Three of them back to back is a noticeable chunk of the startup lag, and the third one lands half a minute after boot, which is exactly when things feel worst.

Changes:

- a marker keyed by `/proc/sys/kernel/random/boot_id`, so only the first caller applies and the rest skip. Whatever starts first wins; order does not matter.

- `appwatch` seeds `last` with the current base profile instead of an empty string, so startup no longer triggers a redundant apply.

- `post-fs-data` removes the previous boot's marker.

Verified: same boot id applies once then skips, a new boot id applies again.
