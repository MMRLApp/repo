Install through the KernelSU manager under Modules - Install from storage, then reboot.

The IO scheduler was the main cause. Samsung ships `ssg` as the default scheduler on this device, and the module replaced it with `none`. Every block IO goes through that scheduler, so changing it makes everything feel one beat slower: back gesture, opening a chat, even loading the WebUI.

The scheduler is only replaced now if the current one is `cfq` or `deadline`, both old and long past their best. Vendor schedulers (`ssg`, `none`, `mq-deadline`, `bfq`, `kyber`) are left alone.

Each apply also restores the recorded original first, then decides whether to change anything. That means simply installing this and applying once puts `ssg` back for you; no manual revert needed.

Also in this build:

- `read_ahead_kb` dropped a lot: 128 power save, 256 balanced, 512 performance, 1024 gaming. It used to write 2048 on performance, against a stock value of 128. Over-reading hurts random IO more than it helps.

- performance and gaming keep `walt` if the kernel has it, instead of forcing `performance`. Samsung defaults to `walt`; forcing `performance` just builds heat and gets throttled later.

- turning a switch off now actually restores the node. `CPU_GOV`, `CPU_FREQ`, `IO_SCHED` and `READ_AHEAD` restore their recorded originals when disabled. Before, disabling only stopped future writes, so anything already changed stayed changed, which is why flipping switches did nothing.
