This is the actual cause of the lag. The IO scheduler I changed last release was a real problem, but not the main one.

`initrc` starts `KernelSU-Tuner_watch` with `appwatch.sh run` directly, which skips the switch check that lives in the `start` branch. So with `APPWATCH=0` the foreground polling kept running anyway. You can see it in the log you sent:

```
13:45:31 启动
13:45:36 默认 -> balanced
13:51:11 默认 -> performance

```

That is the appwatch loop, while the switch was off.

What it does every 3 seconds is `dumpsys activity activities`. That is one of the heaviest commands in Android and it holds the ActivityManager lock while it builds its output. The back gesture, launching WeChat, opening the WebUI all need that same lock, so everything waits a beat and then continues, over and over.

Fixes:

- `run_loop` checks the switch itself now and exits immediately when it is off, so it cannot be started around the check any more.

- the poll interval went from 3 seconds to 10.

- `fg_pkg` tries `dumpsys window` first, which is far smaller. It only falls back to `dumpsys activity activities` if that returns nothing.

After installing, reboot. The old polling process belongs to the previous version and only goes away on restart.
